## argon2-browser — vendored bundle

**File:** `frontend/static/argon2-bundled.min.js`
**Upstream:** [argon2-browser](https://github.com/antelle/argon2-browser) v1.18.0
**License:** MIT
**SHA-256:** `77c64b946baf1a5116dc591f4b9965d636b1b455f75edd2d4a587cb75e01687b`

This file is byte-identical to `dist/argon2-bundled.min.js` from the published
`argon2-browser@1.18.0` npm package — verify with:

```bash
sha256sum frontend/static/argon2-bundled.min.js
# 77c64b946baf1a5116dc591f4b9965d636b1b455f75edd2d4a587cb75e01687b
```

It is served as a separate `<script>` rather than bundled by Vite because
`frontend/src/lib/crypto.ts` pins it with a Subresource Integrity hash
(`ARGON2_SRI`). Argon2 derives the key that protects every health entry; the
SRI pin is what stops a compromised frontend host from swapping in an Argon2
that exfiltrates passwords before they are ever hashed.

> **Do not edit this file — not even to add a license header.** Any byte change
> invalidates `ARGON2_SRI` and the browser refuses to load the script, which
> breaks registration and login. That is why the attribution lives here rather
> than in a banner comment. If you update the bundle, regenerate the hash:
> `openssl dgst -sha384 -binary frontend/static/argon2-bundled.min.js | base64 -w0`
